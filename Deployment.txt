Phase 1: Decide the deployment strategy

note-observability-microservices/

├── auth-service/
├── notes-service/
├── gateway/
├── docker-compose.yml
├── prometheus/
├── .github/

That means:

one Git repository
one Docker Compose
one VPS
one deployment

This is called a Monorepo CI/CD.

Phase 4: Modify docker-compose for Production


Currently you use:

auth:
  build:
    context: ./auth-service

This works for development only.

Production should use images.

Example:

auth:
  image: yourname/auth-service:latest


Likewise:

notes:
  image: yourname/notes-service:latest


Gateway:

gateway:
  image: yourname/gateway:latest

Leave build: in your local compose, but create a separate docker-compose.prod.yml for the VPS.
